# CNV VAF Validator 1.0.0

## Overview

`cnv-vaf-validator` is a command-line post-calling validation tool for deletion and duplication candidates from short-read whole-genome sequencing (WGS): it generates full read-depth profiles for submitted genomic regions and automatically classifies them as `DEL`, `DUP`, or diploid (`DIP`) using a coverage-image CNN, a variant-allele-frequency (VAF) SVC, or both models independently. The tool is intended for technical review and prioritization rather than de novo CNV discovery or clinical interpretation, and accepts CNV calls supplied as a positional table, native ClinCNV output, Manta VCF, or a multi-sample manifest; coverage analysis requires a coordinate-sorted, indexed BAM/CRAM file, while VAF analysis additionally requires a sample-matched small-variant VCF containing genotype-level `VAF`, `AF`, or allele-depth (`AD`) values.

`cnv_vaf_validator.py` validates `DEL`, `DIP`, and `DUP` calls with a VAF SVC model, a coverage-image CNN, or both. Full coverage profiles and VAF train-space plots are generated by default, and every sample receives its own output directory and TSV files.

## INSTALLATION ISSUES

You may encounter a problem caused by the absence of `libmkl_gf_lp64.so.3`. It can be solved by running the following command inside the `cnv-vaf-validator` environment:

```bash
mamba install "mkl<2026.2"
```

## Installation

0) In order to install this tool, you need to have `mamba>=2.5.0`.

1) Clone this repository:

```bash
git clone http://git.ripcm.com/azimin/cnv-vaf-validator
```

2) Run the installer:

```bash
bash cnv-vaf-validator/install.sh
```

You can also create the environment manually:

```bash
mamba env create -n cnv-vaf-validator -f cnv-vaf-validator/environment.yml
```

Then run the installer:

```bash
bash cnv-vaf-validator/install.sh
```

3) Activate the environment:

```bash
mamba activate cnv-vaf-validator
```

4) The tool can be called from any directory using either installed command:

```bash
cnv-vaf-validator
cnv-vaf-validator.py
```

## Quick test

The installed package includes ClinCNV calls, a small-variant VCF, and a CRAM in `example/`. Run the complete VAF + CNN workflow with:

```bash
cnv-vaf-validator.py --test-run
```

The result is written under:

```text
test_run/
└── single_sample/
    ├── OUTPUT_VAF.tsv
    ├── OUTPUT_CNN.tsv
    ├── OUTPUT_COMBINED.tsv
    ├── coverage_profiles/
    └── vaf_train_dimension/{DEL,DIP,DUP}/
```

## Accepted CNV-call inputs

`--cnvs` is auto-detected as one of the following:

1. A standard TSV/CSV table.
2. Native ClinCNV output with a `#chr ... CN_change` header.
3. A plain or gzip-compressed Manta VCF whose metadata identifies Manta.
4. A multi-sample ClinCNV/Manta manifest.

Standard multi-sample layout:

```text
sample_id  chr  start  end  SVTYPE
```

Standard single-sample layout:

```text
chr  start  end  SVTYPE
```

Header names in standard tables are ignored; columns are identified by position. Coordinates are 1-based inclusive. Only `DEL`, `DIP`, and `DUP` are supported. `INS`, `BND`, and `INV` are not validation classes. Unsupported Manta records are skipped; unsupported values in a standard table are reported as an input error.

For ClinCNV, the expected autosomal copy number is 2. The `##gender of sample` metadata changes sex-chromosome baselines: male X/Y use CN 1, female X uses CN 2, and female Y uses CN 0. Values below/equal/above the expected CN become `DEL`/`DIP`/`DUP`.

For multi-sample native ClinCNV/Manta outputs, use a TSV or pipe-delimited manifest:

```text
sample_id | cnvs | bam/cram | vcf
SAMPLE_1 | calls/SAMPLE_1.clincnv.tsv | bam/SAMPLE_1.cram | vcf/SAMPLE_1.vcf.gz
SAMPLE_2 | calls/SAMPLE_2.manta.vcf.gz | bam/SAMPLE_2.bam | vcf/SAMPLE_2.vcf.gz
```

## Validation modes

Defaults:

```text
--verbose true
--vaf-validation true
--cnn-validation false
--plot-cov true
--plot-vaf-train-dimension true
```

Progress logging is enabled by default in every mode. The tool reports input
detection and manifest expansion, per-sample processing, coverage generation,
model inference, and output writing to standard error. Use `--verbose false`
to suppress progress messages; warnings and errors are still printed.

Because full profiles are enabled by default, an indexed BAM/CRAM is required even for a default VAF-only run. Use `--plot-cov false` when no profiles are needed.

VAF train-space JPEGs are independent of coverage plotting and require no BAM/CRAM. Disable them with `--plot-vaf-train-dimension false`.

VAF only, without coverage profiles:

```bash
cnv-vaf-validator.py \
  --cnvs calls.tsv \
  --vcf-dir /path/to/vcf_files \
  --output results \
  --plot-cov false
```

CNN only:

```bash
cnv-vaf-validator.py \
  --cnvs calls.tsv \
  --vaf-validation false \
  --cnn-validation true \
  --alignment-dir /path/to/alignments \
  --output results
```

VAF + CNN:

```bash
cnv-vaf-validator.py \
  --cnvs calls.tsv \
  --vcf-dir /path/to/vcf_files \
  --alignment-dir /path/to/alignments \
  --vaf-validation true \
  --cnn-validation true \
  --output results \
  --threads 8
```

Single-sample validation uses `--vcf-path` for VAF and `--alignment-path` for CNN or profiles:

```bash
cnv-vaf-validator.py \
  --cnvs ClinCNV_output.tsv \
  --vcf-path sample.small_variants.vcf.gz \
  --alignment-path sample.cram \
  --output results
```

The small-variant VCF used for VAF extraction may be plain or gzip-compressed and must contain VAF in `FORMAT/VAF`, or `FORMAT/AF` and `FORMAT/AD`.

Coverage-only mode is preserved and performs no validation:

```bash
cnv-vaf-validator.py \
  --mode plot-cov \
  --cnvs calls.tsv \
  --alignment-dir /path/to/alignments \
  --plot-dir coverage_plots
```

## Output directory schemes

`--output` is required in validation mode. It supports two layouts.

### Ordinary output directory

```bash
--output /path/to/output_dir
```

The tool adds a directory for every sample:

```text
/path/to/output_dir/
└── SAMPLE_ID/
    ├── OUTPUT_VAF.tsv
    ├── OUTPUT_CNN.tsv
    ├── OUTPUT_COMBINED.tsv
    ├── coverage_profiles/
    │   ├── DEL/
    │   ├── DIP/
    │   └── DUP/
    └── vaf_train_dimension/
        ├── DEL/
        ├── DIP/
        └── DUP/
```

### Sample-aware output mask

```bash
--output "/path/to/{sample_id}/output_dir"
```

For sample `HG03251`, files are written directly to the substituted directory; an additional `HG03251` directory is not created:

```text
/path/to/HG03251/output_dir/
├── OUTPUT_VAF.tsv
├── OUTPUT_CNN.tsv
├── OUTPUT_COMBINED.tsv
├── coverage_profiles/{DEL,DIP,DUP}/
└── vaf_train_dimension/{DEL,DIP,DUP}/
```

In single-sample mode, the internal sample name is `single_sample`; the `SAMPLE_ID` column is omitted from all TSV files.

## Files produced by each mode

| VAF | CNN | `--plot-cov` | Result |
|---:|---:|---:|---|
| true | false | true | `OUTPUT_VAF.tsv` and full profiles |
| false | true | true | `OUTPUT_CNN.tsv` and full profiles |
| true | true | true | All three TSV files and full profiles |
| true | false | false | `OUTPUT_VAF.tsv` only |
| false | true | false | `OUTPUT_CNN.tsv`; CNN inputs remain internal and temporary |
| true | true | false | All three TSV files without public profiles |
| false | false | any | Invalid combination |
| `--mode plot-cov` | — | — | Profiles only; no validation TSV files |

When VAF validation is enabled, `--plot-vaf-train-dimension true` additionally creates one JPEG per CNV with plottable VAF features under `vaf_train_dimension/{DEL,DIP,DUP}/`. This is independent of `--plot-cov`.

`INPUT_REGION_COVERAGE` always points to the full user-facing profile. It is `NA` when `--plot-cov false` or when that profile could not be created. It never points to the legend-free technical image used by the CNN.

## Output tables

All column names are uppercase. In multi-sample mode the common prefix is:

```text
SAMPLE_ID CHR START END INPUT_SVTYPE PREDICTED_SVTYPE
INPUT_OUTPUT_CONSISTENCY MODEL_ELIGIBILITY LOW_MAPPABILITY_REGION
INPUT_REGION_COVERAGE
```

In single-sample mode `SAMPLE_ID` is omitted.

`OUTPUT_VAF.tsv`:

```text
SAMPLE_ID CHR START END INPUT_SVTYPE PREDICTED_SVTYPE
INPUT_OUTPUT_CONSISTENCY MODEL_ELIGIBILITY LOW_MAPPABILITY_REGION
INPUT_REGION_COVERAGE NUM_OF_VARIANTS MARKER_0.33 MARKER_0.66
MARKER_0.33+0.66 MARKER_0.5 MARKER_1
MODEL_SCORE_DEL MODEL_SCORE_DIP MODEL_SCORE_DUP CNV_POSITION_IN_TRAIN_DIMENSION
```

`MODEL_ELIGIBILITY` is `ELIGIBLE`, `INSUFFICIENT_NUM_VAR`, or `ERROR`.

`OUTPUT_CNN.tsv`:

```text
SAMPLE_ID CHR START END INPUT_SVTYPE PREDICTED_SVTYPE
INPUT_OUTPUT_CONSISTENCY MODEL_ELIGIBILITY LOW_MAPPABILITY_REGION
INPUT_REGION_COVERAGE NN_PROBABILITY_DEL NN_PROBABILITY_DIP NN_PROBABILITY_DUP
```

CNN `MODEL_ELIGIBILITY` is `ELIGIBLE` or `ERROR`.

`OUTPUT_COMBINED.tsv`:

```text
SAMPLE_ID CHR START END INPUT_SVTYPE VAF_PREDICTED_SVTYPE
NN_PREDICTED_SVTYPE FINAL_DECISION
```

Predicted types are `DEL`, `DIP`, `DUP`, or `NA`. `INPUT_OUTPUT_CONSISTENCY` is `CONSISTENT`, `INCONSISTENT`, `NOT_CNV`, or `NA`. `LOW_MAPPABILITY_REGION` is `CENTROMERIC`, `TELOMERIC`, `CENTROMERIC;TELOMERIC`, or `NA`.

`MARKER_0.33+0.66` is the sum of `MARKER_0.33` and `MARKER_0.66`. `CNV_POSITION_IN_TRAIN_DIMENSION` is an absolute path to the CNV JPEG in the two-dimensional `X0.33_X0.66` versus `X0.5` training projection, or `NA` when plotting is disabled or unavailable.

`FINAL_DECISION` is the input class when every available prediction supports it, `CNV_not_input type` when an available prediction contradicts it, and `NA` when neither model produced a prediction.

## Missing files in multi-sample mode

A failure for one sample does not stop other samples. VAF failures become `MODEL_ELIGIBILITY=ERROR`; CNN failures become `MODEL_ELIGIBILITY=ERROR`; failed public plots receive `INPUT_REGION_COVERAGE=NA`. Missing native caller output in a manifest skips that manifest row.

## Models

Bundled model files and VAF plotting data are stored in `models/` and `data/`:

- `models/svc_vaf.pkl` — `SVC(C=1.0, class_weight=None, coef0=0.0, gamma="scale", kernel="sigmoid", probability=True)`;
- `models/CNN_coverage.pt` — coverage-image CNN checkpoint.
- `data/VAF_train.tsv` — train features used for VAF train-space plots.

The SVC input order is `X0.5`, `X1`, `X0.33_X0.66`, where `X0.33_X0.66 = X0.33 + X0.66`. Encoded classes are `0 = DEL`, `1 = DIP`, and `2 = DUP`.

## Coverage behavior

BAM/CRAM files must be coordinate-sorted and indexed; CRAM decoding must have access to its reference. Public profiles have axes, legend, grid, and CNV boundary lines by default.

For very large regions, plots use median coverage inside windows instead of coverage at every position: 100-bp windows first, then 1,000 bp, 10,000 bp, and subsequent powers of ten when required.
